## Start here

1. Find your team under **Organization → Teams**, then open its **Projects** tab.
2. Open your team's **Kanban board**. Look at your assigned tasks and update them as you work.

## Five terms you'll encounter on GitHub

| Term | Meaning |
|---|---|
| **Organization** | Our association's shared GitHub workspace. |
| **Team** | A group of members. These can be teams within Asclepios or working group's for a project. Teams help manage access. |
| **Issue** | One task or work-package. You can assign an owner (responsible for task), add a description or add progress updates. |
| **Project** | A board, table, or roadmap that organizes Issues (tasks). One Issue can be shown in more than one project. |
| **View** | Different ways to see the same tasks, such as Kanban board or timeline. View's are the tabs you find within a project. |
| **Repository** | Where tasks and related documents are stored. |

To manage tasks, you will primarily use the "Projects" section. There you will create and update tasks. You'll not need to think about the repository and team sections too much. We will mainly use those sections to organise task and member access.

## Working with tasks (everyone)

1. Open your team's **Project** and choose its **Board** (Kanban) view.
2. To create work, use **Add item → Create new issue** and select your team's repository. Give it a short, actionable title (for example, *Prepare October outreach plan*).
3. Describe what needs doing, assign the person responsible, and add a due date if useful.
4. Move the card between **Todo → In progress → Done** as work progresses. Add comments or mention `@username` when you need input.
5. If another team needs to see the same task, add the Issue to their Project too **if you have access**. Remember: it's still one shared Issue, not a separate task.

## Creating a new team workspace (team leads and members setting up a project)

1. Check whether your team already has a **repository** and **Project**. 
2. Under the **organization** (not your personal profile), create a private repository for the team's Issues, if needed. Enable **Issues** in it's settings.
3. Under **Organization → Projects → New project**, create a **Board** Project, preferably using the association's template if one exists. Give it an identifiable team name.
4. Make **Status** the board's columns (e.g., Todo, In progress, Done). Add the team's repository as its default repository, if applicable.
5. In **Project → Settings → Manage access**, give the team **Write** access and its coordinators **Admin** access. Set access for other association members according to the type of work.
6. Give the team suitable access to the underlying **repository**, too. Project access alone does not grant access to private repository Issues.
7. Link the new Project from the team's page and notify your VP or team head.

> **Privacy:** Don't put executive, personal, or otherwise confidential information into a general team repository or board. Ask an organization owner if you need a restricted workspace.
